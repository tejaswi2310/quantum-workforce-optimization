# Phase 4 Implementation Plan: Diagnosis & Fixes

## 1. Diagnosis
**Task 1: Forecast Schema (`lower_bound` / `upper_bound`)**
- `data/processed/forecast_results.csv` contains `predicted_calls` but does **not** contain `lower_bound` or `upper_bound`. The Random Forest regressor does not naturally output prediction intervals without quantile regression or bootstrapping, which is not implemented. The dashboard crash is due to trying to multiply non-existent columns.

**Task 4: Queue Validation (100% SLA)**
- The 100% SLA is a mathematically valid artifact of two factors:
  1. **Shift Rigidities**: The shift optimizer enforces 8-hour blocks. If hour 9 requires 42 agents, hours 10-12 might also receive 42 agents even if demand drops, leading to massive overstaffing in specific hours.
  2. **Erlang-C Economies of Scale**: The Classical Optimizer computes agent requirements *per skill group* and *per channel* (segmentation). The Queue Simulator validates the center as a *single pooled queue*. The sum of agents required for segmented queues is always much larger than the agents required for a single pooled queue with the same total traffic. Thus, validating segmented staffing levels against a pooled traffic model naturally yields near 0% wait probabilities and 100% SLA.

**Task 5 & 6: Classical & Shift Optimization**
- The solver formulates a true MIP. `num_agents = 120` is deterministically seeded (`np.random.seed(42)`) to synthesize the available workforce pool, which is mathematically sound for a synthetic scenario.

**Task 7: Quantum Optimization**
- QAOA is explicitly constrained to a 2-hour, single-skill sub-problem (Technical, 10:00-12:00, 8 variables). It is mathematically genuine but only a demonstration.

**Task 8: FastAPI Startup**
- Windows requires `python -m uvicorn ...` instead of `uvicorn ...` because the pip `Scripts` directory isn't always in PATH.
